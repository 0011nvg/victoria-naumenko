# Виктория Науменко — персональный сайт

Опубликованный адрес: https://0011nvg.github.io/victoria-naumenko/

Лёгкий статический сайт без внешних библиотек, CDN, аналитики и серверной части. Весь текст находится в HTML, поэтому содержание, ссылки и навигация доступны без JavaScript. JavaScript улучшает мобильное меню и добавляет короткие анимации появления. Учитывается `prefers-reduced-motion`.

## Где менять содержание

| Файл | Что редактировать |
|---|---|
| `content.json` | Проекты, направления работы, достижения, принципы |
| `template.html` | Первый экран, биография, контакты, метатеги |
| `styles.css` | Цвета, шрифты, размеры, адаптивность |
| `script.js` | Мобильное меню и анимация |
| `assets/` | Портрет, реальные скриншоты проектов, социальная карточка |
| `index.html` | Готовая страница для GitHub Pages; создаётся сборкой |

### Обычное обновление

1. Создайте рабочую ветку от `main`.
2. Измените текст в `content.json` или `template.html`.
3. Выполните `python3 tools/build.py` (нужен Python 3, установка пакетов не требуется).
4. Выполните `python3 tools/check.py` и `node --check script.js` (для второй команды нужен Node.js).
5. Добавьте в коммит как исходники, так и обновлённый `index.html`.
6. Откройте pull request, проверьте изменения и объедините его. GitHub Pages публикует ветку `main`, папку `/ (root)`.
7. После завершения `pages build and deployment` откройте сайт и проверьте обновлённые разделы.

Не редактируйте только `index.html`: следующая сборка перезапишет такие изменения. Для простой правки через веб-интерфейс GitHub попросите помощника изменить источник и пересобрать страницу в той же ветке.

### Как добавить проект

Скопируйте объект в массиве `projects`. Укажите уникальный `id`, порядковый `number`, название, описание, аудиторию, точный HTTPS-адрес, путь к превью и его `alt`. Для готового проекта оставьте `status` и `note` пустыми. Поле `tags` — короткий список реально работающих возможностей. Если проектов станет больше трёх, проверьте также формулировки о числе проектов в `template.html`; цифра в нижней строке первого экрана обновляется автоматически.

Превью — настоящие снимки проектов, сделанные 30 октября 2026 года. Их следует обновлять, когда внешний вид этих сайтов заметно меняется. Веб-превью рекомендуется сохранять в WebP, шириной около 1200 px. Не заменяйте их вымышленными интерфейсами.

### Достижения, события, фотографии и дипломы

Добавьте объект в `achievements`: `label` — категория, `title` — полное название, `text` — подтверждённый результат и при необходимости год. Для нового профессионального события можно использовать тот же формат. Не добавляйте неподтверждённые награды или даты.

Портрет подключён в двух размерах: `victoria-600.webp` и `victoria-1000.webp`. При замене сохраните пропорции либо обновите `width`, `height`, `srcset`, `sizes` в шаблоне. Отдельно обновите `assets/social.jpg` (1200 × 630 px).

Галерея дипломов сейчас намеренно отсутствует. Когда документы будут готовы, её можно добавить отдельной секцией в `template.html` с миниатюрами и ссылками на оригиналы в `assets/`, без переделки остальных разделов. Перед публикацией проверьте персональные данные на документах.

### Контакты

Единственный внешний контакт — ВКонтакте: https://vk.ru/designingthefuture. При смене ссылки обновите её также в JSON-LD и `tools/check.py`. Телефон, почта и GitHub в контактном разделе не публикуются.

## Проверка и ограничения

Результаты текущей проверки: [QA.md](QA.md). Проверка ширин в Chromium не заменяет проверку на физическом iPhone/Safari. Сайт не использует сервис-воркер: при смене версии нет старого офлайн-кэша.

Корневая `.nojekyll` сохраняет обычную статическую публикацию. Все локальные ресурсы имеют относительные пути и работают в подпапке `/victoria-naumenko/`. `sitemap.xml` содержит канонический адрес. `robots.txt` внутри подпапки проекта не добавлен: поисковые системы читают его в корне домена, который не относится к этому репозиторию.

Если потребуется откат, отмените коммит через новый pull request; не переписывайте историю `main`.
